# Unified Recipe Catalogue Phase 2 Two-Source Pilot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run a bounded RecipeTin Eats and Serious Eats catalogue pilot that produces trustworthy discovery, quality, idempotency, latency, storage, Firestore operation, and Gemini-usage evidence without enabling catalogue generation or the Scheduler.

**Architecture:** Extend the dormant Phase 1 ingestion path with additive, source-attributed counters and validated Gemini usage callbacks. Drive three bounded Cloud Run executions (discovery-only, forced targeted sample, unchanged targeted rerun), collect recipe and selector evidence through a read-only Admin SDK verifier, and fail closed unless the safety and quality thresholds pass. The mobile generator, legacy tagger, Scheduler state, and `generationMode` are outside the implementation path.

**Tech Stack:** TypeScript 5.9, Node.js 22 Cloud Run/Functions runtime, Vitest, Firebase Admin SDK, Firestore, Cloud Storage manifests, PowerShell, Google Cloud CLI.

**User decisions (already made):**
- Phase 2 pilots RecipeTin Eats as the existing runtime source and Serious Eats as the existing indexed source.
- The detailed Phase 2 plan must be committed before implementation code changes.
- Implementation uses test-driven development.
- The Cloud Scheduler remains `PAUSED` and `/appConfig/catalogue.generationMode` remains `legacy`.
- Protected HTTP 401/402/403 responses are measured as unsupported outcomes; the pilot never bypasses access controls.
- Relevant local and cloud verification gates must complete before Phase 2 is claimed complete.

## Scope and approach decision

Three implementation shapes were evaluated:

1. **Script-only reporting:** Reuse the Phase 1 global run counters and add only a verifier. This is low risk, but it cannot distinguish the two sources, attribute access failures, count recipe lookups, estimate written document bytes, or attach Gemini usage to a run.
2. **Additive run telemetry plus a pilot verifier (selected):** Keep ingestion behavior unchanged while adding per-source counters, bounded hashed sample IDs, timing, document byte estimates, recipe-read counters, and validated Gemini usage. A read-only verifier audits the written sample and exercises the real Firestore selection query path.
3. **Managed analytics/dashboard:** Export logs and Firestore metrics to a warehouse/dashboard. This would be useful after backfill begins, but adds infrastructure and cost before the pilot establishes which metrics matter.

The selected approach is the smallest one that covers every Phase 2 measurement named in the approved design. All new fields are additive. The original aggregate `metrics`, `reservedWrites`, and `consumedWrites` remain available to existing Phase 1 verification.

## Pilot gates and thresholds

The pilot uses three immutable run IDs generated by the orchestration script:

- `phase2-pilot-<stamp>-discovery`: `--dry-run`, both sources, no page fetch or recipe mutation.
- `phase2-pilot-<stamp>-first`: force-refreshes the curated targets with a command cap of 40 writes.
- `phase2-pilot-<stamp>-second`: repeats the same targets without force refresh under the same cap.

The gate passes only when:

- Scheduler state is exactly `PAUSED` before and after the runs.
- `generationMode` is exactly `legacy` before and after the runs.
- Discovery produces a source-attributed result for both sources. An explicit Serious Eats discovery failure is evidence, not a reason to bypass protection.
- The first target run safely resolves every target as a complete recipe, review record, or bounded unsupported/permanent outcome, with no retryable or unbounded failure.
- The second target run reports zero page fetches and zero recipe-document writes.
- Every sampled `ready` document passes `validateReadyRecipe`, has time and taxonomy metadata, and has search fields consistent with effective metadata.
- The sample contains at least one ready RecipeTin Eats recipe. Serious Eats may remain `disabled / unsupported-402` if Cloud Run continues to receive HTTP 402.
- The measured selector path runs at least 10 iterations, returns only `selected` or explicit `no-match`, and has p95 latency no greater than 2,000 ms.
- The evidence reports candidate document reads, estimated serialized bytes, run writes, and Gemini calls/token counts. These are labelled application-level measurements rather than Firestore billing exports.

```js
export function validateCataloguePilotEvidence(evidence) {
  if (evidence.schedulerState !== 'PAUSED') throw new Error('Scheduler is not PAUSED');
  if (evidence.generationMode !== 'legacy') throw new Error('generationMode is not legacy');
  if ((evidence.second.metrics?.fetched ?? -1) !== 0
    || totalDocumentWrites(evidence.second) !== 0) {
    throw new Error('Second pilot run was not idempotent');
  }
  if (evidence.audit.readyRecipeTin < 1
    || evidence.audit.invalidReady > 0
    || evidence.audit.searchMismatches > 0
    || evidence.audit.missingTime > 0
    || evidence.audit.missingTaxonomy > 0) {
    throw new Error('Pilot recipe quality gate failed');
  }
  if (evidence.selection.iterations < 10 || evidence.selection.p95Ms > 2_000) {
    throw new Error('Pilot selection latency gate failed');
  }
  // Validate both source outcomes and all non-negative measurement fields.
}
```
